# RPC 重试不能重复执行

网页发送控制请求后，响应可能丢失。请改进 AppServer：对具有副作用的请求使用
`request_id` 实现持久化去重，避免重试重复创建会话、启动任务或保存凭据。
这是服务端控制面的任务，不是模型 Provider 的 HTTP 重试，也不是前端按钮防抖。

## 公开验收要求

- 同一个 ID、相同 method 和语义相同的 params，完成后重试应返回原响应，不重复执行。
  JSON 对象键的排列不影响身份；不同 ID 是不同请求。
- 两个有副作用请求使用同一个 ID 但不同 method 或 params，返回 `idempotency_conflict`，不执行第二个请求。
- 重启服务后，仍能回放已经完成的响应，包括正常返回的错误响应。
- 接收记录必须在分派副作用之前持久化。接收记录保存失败时，返回 `storage_error`，
  不进入业务分派。
- 已接收但结果未知的请求，不管崩溃发生在业务执行前还是执行后，重试都返回
  `request_outcome_unknown`，不自动重新执行。不能假装这提供了外部副作用的 exactly-once 保证。
- 业务执行成功但响应记录保存失败时，返回 `storage_error`；随后重试按未知结果处理。
- `session.list` 等只读查询不能被去重缓存，必须反映最新数据。
- 兼容已有 schema 3 数据库，原有会话数据不能丢失。保留现有 RPC 接口和测试。
- 去重元数据不得保存原始 API key。测试使用模拟凭据，不连接真实 Provider。

范围：现有 AppServer 控制面的有副作用方法，尤其是 `session.create`、`turn.start`、
`provider.credential.set`。可以新增内部模块；不要求特定表名、哈希算法或参考补丁结构。
请增加有效回归测试并运行相关测试。最终说明修改和验证情况，回答格式不参与功能评分。

测试环境提供 Python 和项目依赖，无网络、宿主凭据或其他仓库。不要安装依赖、调用真实模型、
修改已有测试来规避失败、修改评测器或尝试读取环境外文件。
